## 3. Sucessos

- **Padrão propose/commit provado.** O toolkit como único escritor + adapter pass-through foi a decisão arquitetural mais importante do projeto. Nenhum agente escreve diretamente — todo artefato passa pelo commit com SHA-256.
- **Checkpoint/resume atômico.** WAL + quarentena de órfãos funcionou desde o primeiro commit. A retomada de sessão é determinística.
- **Confiança mecânica.** Atribuição 🟢🟡🔴 por presença de fonte, validada pelo toolkit, não pelo LLM. A base do rigor herdado do Reversa.
- **Scaffold + bootstrap.** A instalação via adapter funcionou — `/process-ai` registrado no Claude Code sem passos manuais.
- **Code review adversarial 3 camadas.** Blind Hunter + Edge Case Hunter + Acceptance Auditor pegaram dezenas de itens antes do merge.

---

## 4. Desafios

- **Múltiplos rounds de hardening.** O code review da 1.1 gerou 13 patches; o da 1.2 gerou findings de WAL/quarentena que foram endereçados na 1.3. O padrão "code review → patches → re-review" foi caro mas eficaz.
- **Ambiente Windows.** Symlink tests pulados (requer Developer Mode/admin). Cleanup de teste com EBUSY latente.
- **Pipeline mínima vs profunda.** Os "rascunhos" da 1.6 eram funcionais mas superficiais — o contraste com o Épico 2 (profundo) foi significativo.

---

## 5. Insights-chave

- **Toolkit determinístico é load-bearing.** Toda garantia do produto (não-destrutivo, confiança, checkpoint) vive no toolkit Node, não nos agentes LLM.
- **Adapter pass-through é suficiente.** O ClaudeCodeAdapter não precisa interpretar o payload — só rotear. Isso simplificou o design e provou a porta EngineAdapter.
- **WAL antes de aplicar.** O padrão "gravar intenção → aplicar → marcar completo" evitou corrupção de estado em todos os cenários de crash.
